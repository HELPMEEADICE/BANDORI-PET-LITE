# Rust 渲染路径优化

`.moc` 与 `.moc3` 都通过 `pet-render::ModelGpu` 和 `SceneRenderer` 绘制。
优化位于应用层，不修改 `vendor/neocari`，也不改变动画、物理、动作或表情的更新顺序。

## 每帧开销

- 保存模型的裁剪计划。几何变化时只重新计算裁剪边界和矩阵，复用分组及成员列表；
  可见性、掩码、拓扑发生变化时重新分组，保持部件淡入淡出和反向掩码正确。
- 没有可见裁剪组时，跳过掩码通道，使用无裁剪绘制路径。
- 全分辨率、不透明度为 100%、窗口使用预乘 Alpha 时，直接绘制到窗口表面，
  不分配中间纹理、不执行全屏 blit。模型纹理自身的半透明像素仍参与 Alpha 混合。
- 省电画质、窗口透明度以及其他表面 Alpha 模式继续使用中间纹理。
  切换设置时自动创建或释放纹理，窗口尺寸变化时按需重建。
- FPS 计数器合并到最终绘制通道，避免额外加载、保存窗口图像。

全分辨率、100% 不透明度、预乘 Alpha 表面的通道数量如下：

| 模型状态 | 原路径 | 优化后 |
| --- | ---: | ---: |
| 无可见裁剪组，关闭 FPS | 3 | 1 |
| 无可见裁剪组，开启 FPS | 4 | 1 |
| 有可见裁剪组，关闭 FPS | 3 | 2 |
| 有可见裁剪组，开启 FPS | 4 | 2 |

以上是通道和资源开销的变化，不代表特定硬件上的 FPS 提升百分比。

## 回归验证

Linux CI 安装 Mesa 软件 Vulkan 驱动，运行 `gpu_render_regressions`。
测试使用合成网格与透明纹理，不依赖角色素材或本机 GPU：

- 将复用的裁剪计划与每帧重新创建的计划比较，同时检查几何变化时分组存储得到复用。
- 覆盖几何移动、可见性切换、掩码集合变化、索引和 drawable 数量变化、空掩码组。
- 覆盖 `.moc` 的 Y 翻转及 Screen 混合，以及两种格式共享的普通、加法、乘法、
  普通裁剪和反向裁剪。
- 将实际优化路径与原中间纹理、blit、独立 FPS 通道的结果逐像素比较。
  覆盖线性 RGBA、sRGB BGRA 表面、全画质、省电画质、窗口透明度和 FPS 开关；
  允许每通道最多 1 个 8 位量化单位的差异。

这验证共享渲染封装的正确性；真实角色的完整动画和驱动相关性能仍需在目标硬件上测量。
